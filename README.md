# Sample DOC MBE

This pack will read, consult, and interpret sample doc files (.doc) created by MBE users during their growth.

Generated by `pack_kit.scaffold`. What is here **runs**; what this pack **knows**
is still to be written — its memory stays empty until you have fed it documents.

---

## What a pack is

A specialist that answers **from what is written down**, not from what a model
remembers. Four pieces, and that is the whole idea:

| | |
|---|---|
| **documents** | what you declare in `sources.yaml` — pages, sites, files on your disk |
| **a vocabulary** | `ontology/schema.ttl` — the nouns of your subject, which decides what can be extracted |
| **a memory** | `memory/sample_doc_mbe.db` — a graph of facts, built by reading the documents |
| **a prompt** | `prompts/lead.md` — who the agent is, and the traps of your subject |

A pack **never carries a model**. Whoever runs it decides which LLM serves it,
so the same pack works on a laptop, on a cluster, or inside a platform.

That is what this structure buys you: your knowledge stops being a folder of
documents nobody re-reads and becomes something that can be **asked a question**,
that says *"this is not in my memory"* rather than inventing, and that can be
handed to a colleague as a directory.

## The files, and who they belong to

```
sample_doc_mbe/
  config.yaml          the agent your users get — read-only memory, no network
  config_admin.yaml    the same agent for YOU — network, ingestion, purge
  sources.yaml         WHAT IT LEARNS FROM        ← you write this
  ontology/schema.ttl  the nouns of your subject  ← you write this
  prompts/lead.md      who the agent is           ← you write this
  prompts/curator.md   your own assistant, for exploring and curating
  memory/*.db          the graph — built by learning, never edited by hand
  learn.sh  serve.sh   links into pack-kit — never copies, never edited
  sandbox/             where the agent writes files
```

**Yours to change, freely:** `sources.yaml`, `ontology/schema.ttl`,
`prompts/lead.md`, `prompts/curator.md`, and the `pack:` block at the top of
`config.yaml` (its name, version, description).

**Change with care:** the rest of `config.yaml` — which tools the agent gets,
what it may do. The comments in the file explain each line; the important one is
that a user's agent has **no network and cannot write to the memory**. That is
structural, not a setting to relax casually.

**Never edit by hand:** `memory/sample_doc_mbe.db` (it is rebuilt by reading your
sources), and `learn.sh` / `serve.sh` (they are links to one shared copy — a
second copy drifts within a day).

## Adding documents — the part you will do most

Everything lives in `sources.yaml`. Three ways in.

### A single page

```yaml
sources:
  - id: the-reference
    url: "https://example.org/manual.html"
    mode: page
    about: >-
      What this page is, in one sentence.
    learn: |
      What to take from it, and what will be asked of it later.
```

### A whole site

```yaml
  - id: the-docs
    url: "https://example.org/docs/"
    mode: site
    max_pages: 25        # a ceiling, so a crawl cannot run away
    about: >-
      The documentation of …
    learn: |
      …
```

### Files on your own disk

Documents that are not on the web — reports, notebooks, notes — go through a
small Python function you write, in `fetchers/`. It reads your files and hands
back their text; everything after that is the same. The function is named in
`sources.yaml`:

```yaml
  - id: my-notes
    fetcher: "{here}/fetchers/my_reader.py::read_them_all"
    fetcher_args:
      directory: "/home/me/notes"
    about: >-
      …
    learn: |
      …
```

Write the fetcher when your files need decoding (Word, PDF) or when it is worth
skipping what has not changed since the last run. Ask for an example if you need
one — the shape is twenty lines.

### The one rule that decides everything

> **The `learn:` text is handed to the reader word for word.** It is the whole
> difference between *"ingest this page"* and *"ingest the things from this page
> that will be asked about later"*.

Say which numbers matter, which names must be copied exactly, what to ignore.
Vague there, vague in the memory. This is where a pack becomes good or stays
generic, and it costs ten minutes.

### A single document, right now

For something with no URL — one correction, one measurement — open the memory
(`./serve.sh`) and use its **Ingest** box. Anything you add that way will not
come back when the memory is rebuilt, so prefer declaring a source whenever the
document is a file you still have.

## The four gestures

```
./learn.sh --list        what is declared, without running anything
./learn.sh               read every source and fill the memory
./serve.sh               OPEN THE MEMORY in a browser and look at it
agent-slapsci --validate -c config.yaml      must exit 0

agent-slapsci -c config.yaml --terminal      talk to your pack
agent-slapsci -c config_admin.yaml --terminal   your curator: explore, purge
```

On Windows, or anywhere without a shell: `python -m pack_kit.learn .` and
`python -m pack_kit.serve .` do the same thing.

**`./serve.sh` is the one people skip and the one that helps most.** `learn`
fills the memory; this shows you **what actually went in**. Read ten facts and
ask yourself whether *you* could answer your question from them. If not, the fix
is in `ontology/schema.ttl` and in your `learn:` texts — not in the model.

`./learn.sh --coreference` merges duplicate entities. It is slow and belongs on a
schedule, not in your daily loop.

## Two numbers that do not mean what they look like

- **A `✅` means the tool returned.** Tools report failure as ordinary text and
  exit 0 all the same. So `learn.sh` counts rows in the database instead — trust
  that line, not the ticks above it.
- **`dead_letters = 0` is a question, not an answer.** It can mean your
  vocabulary covers everything, or that the reader proposed nothing at all. Look
  at the triplet count first: if it is 0, nothing was learned, whatever else was
  printed.

## Good to know before you go far

**Re-reading a page replaces what it taught before.** Running `./learn.sh` twice
leaves the memory as running it once. That is deliberate: the reason to re-read a
page is that it changed.

**The memory is rebuildable, so experiment.** Delete `memory/sample_doc_mbe.db`, run
`./learn.sh` again, and you are back. Nothing else in the pack is generated.

**One choice is expensive to change: `MEMORY_TRIPLET_MODE`** in the two configs
(`nary` here). Changing it later means re-reading everything, because
the facts already stored have the other shape.

**The first paragraph of `prompts/lead.md` is this pack's description
everywhere** — including what another agent reads to decide whether to hand it a
question. Write it as *when to call this*, not as *what this is*.
